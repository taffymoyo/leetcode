# 706. Design HashMap
## What I learned
* Separate chaining handles collisions by making each bucket a list of `[key, value]` pairs, so keys that hash to the same index just share a bucket
* Storing pairs as mutable lists (not tuples) lets `put` update an existing value in place
* A prime bucket count (1009) helps spread keys more evenly across buckets when keys follow a pattern
* `enumerate` gives the index needed to `pop` the right pair in `remove`
## Approach
1. Create a fixed array of 1009 buckets, each an empty list
2. Hash a key with `key % size` to find its bucket
3. `put`: scan the bucket for the key and update its value if found, otherwise append a new pair
4. `get`: scan the bucket and return the value if the key is found, otherwise `-1`
5. `remove`: scan the bucket and pop the pair if the key is found
## Complexity
Time: O(n / size) average per operation, which is effectively O(1) with the given constraints, and O(n) worst case if all keys collide in one bucket  
Aux Space: O(size + n), the bucket array plus stored pairs
## Bucket Solution
```python
class MyHashMap:

    def __init__(self):
        self.size = 1009  # a prime number spreads keys more evenly
        self.buckets = [[] for _ in range(self.size)]

    def put(self, key: int, value: int) -> None:
        bucket = self.buckets[key % self.size]
        for pair in bucket:
            if pair[0] == key:
                pair[1] = value
                return
        bucket.append([key, value])

    def get(self, key: int) -> int:
        for k, v in self.buckets[key % self.size]:
            if k == key:
                return v
        return -1

    def remove(self, key: int) -> None:
        bucket = self.buckets[key % self.size]
        for i, pair in enumerate(bucket):
            if pair[0] == key:
                bucket.pop(i)
                return
```
