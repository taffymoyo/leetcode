# 2389. Longest Subsequence With Limited Sum
## What I learned
* Sorting works for subsequence problems where order doesn't matter for the sum
* Greedy (smallest first) is optimal when maximizing count with one objective — unlike knapsack where two competing objectives (weight + value) make greedy fail (I got these confused)
* Prefix sums + binary search (bisect) can replace a linear scan for O(log n) per query, though I discovered this from checking other peoples optimal solutions
## Approach
1. Sort nums so we can greedily pick the smallest elements first
2. For each query, linearly scan through sorted nums accumulating a running sum, counting how many elements fit
## Complexity
Time: O(n log n + m * n) where n is len(nums) and m is len(queries)  
Aux Space: O(1) excluding the result array
## Solution
class Solution:
    def answerQueries(self, nums: List[int], queries: List[int]) -> List[int]:
        result = []
        nums.sort()
        for query in queries:
            count = 0
            running_count = 0
            for num in nums:
                if num + running_count <= query:
                    running_count += num
                    count += 1
            result.append(count)
        return result
