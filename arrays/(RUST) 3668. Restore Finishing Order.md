# 3668. Restore Finishing Order
## What I learned
* A HashSet gives O(1) lookups, so filtering order against friends is one pass instead of a nested loop
* friends.into_iter().collect() moves the vector into an iterator and builds a HashSet from it. The type annotation on the left tells collect() what to build
* Borrowing a collection (for num in &order) means every item is a reference (&i32)
* set.contains() takes a &i32, so num goes in as-is. result.push() takes an i32, so it needs *num to turn the reference into a value
* into_iter() consumes friends, so it can't be used afterwards. That's why the lookup has to go through the set
## Approach
1. Put friends into a HashSet for fast lookup
2. Walk through order from first to last finisher
3. If the number is in the set, push it onto the result
4. Return the result, which is already in finishing order
## Complexity
Time: O(n + m) where n is len(order) and m is len(friends)
Aux Space: O(m) for the set, plus the output
## Solution
```rust
use std::collections::HashSet; // set for faster lookup
impl Solution {
    pub fn recover_order(order: Vec<i32>, friends: Vec<i32>) -> Vec<i32> {

        let mut result = vec![];
        let set: HashSet<i32> = friends.into_iter().collect(); // move numbers into an iterator and then into a set through type annotation

        for num in &order {  // borrowing collection means every item inside is a reference
            if set.contains(num) { // contains wants &i32
                result.push(*num);
            }
        }
        result
        
    }
}
```
